## LightDataRT Layout (64×2 RGBA32F)

### Row 0 — Light Data (y=0.25 for sampling center)

Each light occupies 4 texels (16 bytes each):

| Texel Offset | Content | Packing |
|---|---|---|
| +0 | Position.xyz, Type | Type: 0=empty, 1=point, 2=spot, 3=directional, 4=rect |
| +1 | Color.rgb, Intensity | Color = linear RGB (0-1), Intensity = UE lux/cd (raw) |
| +2 | Direction.xyz, Radius | Direction = light forward (传播方向), Radius = attenuation radius (cm) |
| +3 | Extra params | Spot: (InnerCos, OuterCos, 2.0, 0); Rect: (Width, Height, 0, 0) |

### Row 1 — Shadow Camera Basis (y=0.75)

| Texel | Content |
|---|---|
| +0 | ShadowOrigin.xyz, Valid (1=active) |
| +1 | Right/OrthoWidth.xyz, GlobalBias |
| +2 | Up/OrthoWidth.xyz, 0 |
| +3 | Forward.xyz (光轴), TexelSize (1/resolution) |

## Preview Scene vs World Scene

| Path | Collection Method | Sky Ambient |
|---|---|---|
| **World** | `CollectLights(GWorld)` scans TActorIterator | UE SkyIrradianceEnvironmentMap (SH) |
| **Preview** | `SetPreviewLightOverride(PackEnvironmentLightData(...))` | Same SH (from PreviewScene's SkyLight) |

Key difference: Preview lights are orphan components not visible to GWorld. They must be explicitly packed and pushed via `SetPreviewLightOverride`. Sky ambient comes from the same SH pipeline but PreviewScene may have a different SkyLight actor or no SkyLight at all.

## Identified Issues / Hypotheses

### H001 — Intensity Units Inconsistency
**Status:** OPEN — needs experimental verification

The UE `ULightComponent::Intensity` for different light types:
- **Directional Light:** lux (illuminance)
- **Point Light:** candelas (luminous intensity)
- **Spot Light:** candelas
- **Rect Light:** candelas

These are stored directly into LightDataRT at `C.w` (line 384/398/412/426 in Subsystem.cpp). The shader divides by `ToonPI ≈ 3.14` for all types uniformly:
```hlsl
DiffuseLight += C.rgb * (C.w / ToonPI) * NdotL * Atten;
```

**Problem:** lux and candelas are physically different units. A 5.5 lux directional light and a 5.5 candela point light produce vastly different illuminance at the surface. The point light also has distance attenuation while directional does not.

**Risk:** Multi-light scenes with mixed types may have inconsistent relative contributions.

### H002 — DirLight Excludes Intensity for Toon Ramp
**Status:** BY DESIGN — verified

```hlsl
// Line 125 of MMDToonLighting.ush:
DirLight += C.rgb * NdotL * Atten;   // 不含光强：光强不改变 toon 阴影位置
```

This is intentional: toon shadow threshold should not shift when light intensity changes. The `ApplyToonShadow` uses `DirLight` luminance to determine ramp position, independent of intensity.

**Design rationale confirmed.** However, need to verify that weak auxiliary lights don't disproportionately affect the ramp.

### H003 — Face Main-Light Stability
**Status:** OPEN — needs experimental verification

`GetMainLightDirection()` selects the light with highest `C.w` (intensity) as the main light. If two lights have similar intensities, the main light may flip between frames, causing Face SDF shadow to jump.

### H004 — SkyAmbient Source
**Status:** PARTIALLY VERIFIED

`SkyAmbient()` reads `View.SkyIrradianceEnvironmentMap` (SH coefficients from UE). This is the same for both World and Preview, but:
- PreviewScene may have no SkyLight → SH coefficients may be zero
- World with a SkyLight will have non-zero SH
- This could explain different results between preview and world.

### H005 — Preview Override vs World Collection
**Status:** OPEN

Preview path: `SetPreviewLightOverride(PackEnvironmentLightData(...))` bypasses `CollectLights()`. The Pack function uses the same layout as CollectLights, so numerical values should match. But Preview lights are orphan components with no distance culling.

### H006 — Material Classification via Name Keywords
**Status:** CONFIRMED — fragile

`LoadMMDPartParent()` uses string matching on PMX material names. Japanese/Chinese keyword lists may miss edge cases. Skin/Cloth shaders are not connected to parent materials.

### H007 — Shadow vs Toon Ramp Confusion
**Status:** OPEN

MMD ShadowMap (scene occlusion) and Toon NdotL ramp are separate systems. Both multiply into Diffuse/DirLight. Need to verify they don't interact pathologically.

### H008 — Matcap Dependency
**Status:** OPEN

All materials support MatCap (SphereMode 0/1/2). In multiply mode it bakes shadow-like modulation; in add mode it adds specular-like highlights. If scenes look good only with a specific matcap, the core toon lighting may be inadequate.
